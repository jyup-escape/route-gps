# Route GPS 1.1.1 · 巡航速度の上限解除版

1.1.1では巡航速度の15km/h上限を解除しました。0.1km/h以上の有限の数値を入力できます。加減速は継続するため、短いルートや信号間隔によって設定速度に達する前に減速することがあります。電車・時刻表対応はこの版には含みません。

徒歩で通れるルートを検索し、加減速・速度のゆらぎ・確率による信号待ちを再生する疑似GPSアプリです。Android 8.0以上向け。APKは前バージョンと同じ鍵で署名しています。上書き更新できます。

## BlueStacksへのインストール

1. `RouteGPS.apk`をBlueStacksの「APKをインストール」から選ぶか、ウィンドウへドラッグしてください。
2. BlueStacksの設定 → 詳細設定（Advanced）で「Androidデバッグブリッジ（ADB）」を有効にしてください。表示されるポート番号を控えます。
3. ZIPを全部展開して`BlueStacks-Setup.cmd`を実行すると、接続中の端末が1つの場合はAPKのインストールと疑似GPS・位置情報・通知の許可設定を行います。位置再生は自動で開始しません。
4. 接続できない場合は、PowerShellで同梱フォルダを開き、次のように実行してください。`5555`はBlueStacksで表示されたポート番号に置き換えます。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\BlueStacks-Setup.ps1 -AdbPort 5555
```

複数のAndroid端末が接続中なら、表示される端末名を使って`-Serial 127.0.0.1:5555`などで対象を選んでください。別の端末に誤って設定しないため、自動では選びません。

BlueStacksで「仮の現在地情報アプリ」が表示される環境では、アプリ内の「開発者向けオプションを開く」から`Route GPS`を選んでも設定できます。ADBの設定コマンド自体が拒否される環境では、このAPKだけで疑似GPSの許可を取得することはできません。ルート再生がその環境で動く保証はありません。

## ルートを作る

- 始点・経由地・終点を、各行に`緯度,経度`で2〜25地点入力し、「道に沿う徒歩ルートを作成・信号を取得」を押してください。OSRMの徒歩用ルート検索で、歩行者が通れる道に沿った形状を作成します。
- 周回したい場合は、作成前に「周回する」をONにしてください。終点から始点へ戻る区間も徒歩ルートとして検索します。
- 作成すると座標欄は道路に沿った細かい形状に置き換わります。別の経由地で作り直す場合は座標欄を経由地の一覧に置き換えてください。
- すでに道路に沿ったGPXがあれば、そのまま読み込めます。GPXの形状を使うため、通れる道に沿っているかは作成元で確認してください。「このルートの信号を取得」で信号を追加できます。
- GPXは1つのトラック区間（`trkseg`）または1つのルート（`rte`）に対応。トラックとルートが両方ある場合はトラックを使います。最大5000地点・ファイルサイズ5MBです。
- 道路検索は20km以内・生成された形状5000地点以内です。道路検索前の経由地だけの状態では再生できません。
- 道路形状やGPXの各地点を短い区間で補間します。OpenStreetMapのデータが古い・不完全な場合は、通行可否の検索結果も異なる場合があります。
- GPXの記録速度・時刻・標高は使いません。速さはアプリの設定に基づき、標高は0mです。
- プレビューはルート形状を表示する図です。背景の道路地図はありません。
- 初期の座標は東京駅付近の経由地の例です。最初に徒歩ルートを作成してください。同梱の`sample-tokyo-walking.gpx`はOSRMで取得・検証した約1.24kmの徒歩周回ルートです。対応する信号距離は`sample-tokyo-walking-signals.txt`にあります。

座標の例：

```text
35.681236,139.767125
35.682000,139.767125
35.682000,139.768000
```

## 歩き方と信号

初期設定は、巡航速度5km/h、加速度0.5m/s²、減速度0.8m/s²、速度のゆらぎ±15%、赤に当たる確率50%、待ち時間15〜60秒です。

- **歩き始め・発進**：速度0から指定した加速度で速くなります。
- **速さのゆらぎ**：6〜14秒ごとに巡航速度の目標を範囲内で抽選します。瞬間的に速度を切り替えず、設定した加減速度以内で追従します。
- **曲がり角**：ルートの方向変化に応じて目標速度を控えめに下げます。
- **赤信号**：通過ごとに設定した確率で赤に当たるか抽選します。赤なら停止距離を計算して手前から減速し、停止してから待ち時間を数え、再び加速します。青なら停止しません。
- **信号位置**：OSMの`highway=traffic_signals`、`highway=crossing + crossing=traffic_signals`、`crossing:signals=yes`のノードを対象にします。ルートから15m以内のものを対応づけ、近接した信号は25m以内をまとめます。自動取得では登録位置の約2m手前を停止位置とします。
- **位置の補正**：未登録の信号や隣の道路の信号がある場合は、信号欄の「始点からの距離m」を手で修正してください。1行ずつ、またはカンマ区切りです。全長より小さく0より大きい距離、最大500地点です。空欄なら信号待ちはありません。
- **運の要素**：赤・青と待ち時間は、再生を開始するたび、周回するたびに新しく抽選します。同じ信号でも毎回同じ待ち方にはなりません。

この信号待ちはシミュレーションです。実際の信号の現在色や周期、押しボタンの状態、交差点全体の連動は取得しません。巡航速度は0.1km/h以上で上限なし、加減速度は0.05〜2m/s²、ゆらぎは0〜30%、確率は0〜100%、待ち時間は最小・最大とも1〜180秒に対応します。

## 再生

1. 徒歩ルートの作成またはGPXの読み込みを行い、必要なら信号の取得・距離修正を行います。
2. 巡航速度、加減速度、ゆらぎ、赤に当たる確率、待ち時間を設定します。周回では始点と終点が2m以内の閉じたルートが必要です。戻り道を直線で追加することはありません。
3. 「ルートを再生」を押します。正確な位置情報と通知の許可を求められたら許可してください。Androidの位置情報設定もONにします。
4. 他のアプリを開いても、通知付きサービスで再生を続けます。位置は約250msごとに更新し、内部では20ms刻みで速度と距離を積分します。表示とGPSの速度には、巡航速度ではなく現在の速度を使います。
5. 一時停止を押すと減速して止まります。再開時は速度0から加速します。信号待ち中に一時停止すると待ち時間も止まり、再開で残り時間を続けます。
6. 1回再生では終点の手前から減速し、終点で速度0となって位置を保持します。周回では始点に戻っていったん減速停止し、次の周を新しい信号抽選で開始します。
7. 「停止・位置情報を戻す」も減速してから疑似GPSを解除します。設定によって停止まで数秒かかります。通知からも一時停止・停止できます。

表示する所要時間は巡航速度で計算した目安です。信号待ち、ゆらぎ、加減速、曲がり角で実際の所要時間は変わります。長い更新途絶の後に位置を飛ばさないよう、1回に取り込む経過時間は最大5秒です。

## 通信とデータ

道路作成時は指定した座標をFOSSGISのOSRM徒歩ルートサービスへ、信号取得時はルート形状をOverpass APIへ送ります。これらのボタンを押したときだけ通信します。取得済みのルートの再生はオフラインで行います。公共サービスのため通信エラー・利用制限が発生する場合は時間をおいて再試行してください。信号取得に失敗したときは警告を表示し、信号なしの状態を明示します。経由地・ルート・設定は端末内に保存します。

ルート生成：[OSRM / FOSSGIS](https://routing.openstreetmap.de/about.html)。地図・信号データ：© [OpenStreetMap contributors](https://www.openstreetmap.org/copyright)、ODbL。

BlueStacksの標準「位置情報を設定」機能や他の疑似GPSアプリを同時に操作すると競合する可能性があります。停止後に位置がすぐ戻らない場合は、利用中のアプリで位置情報を再取得するか、BlueStacksの標準機能で希望の位置を再設定してください。

アプリ・BlueStacks・PCが終了した場合、再生は続きません。プロセスが再起動しても勝手に再生を再開しません。PCのスリープ中は更新できません。再生中はAndroid側のCPU停止を抑えるためwake lockを使います。

## 検証状況

- APKのコンパイル・v2/v3署名検証：成功。
- 距離計算、加減速度の上限、信号の正確な停止位置、青での通過、待ち時間、終点での減速停止、一時停止と再開、同じ乱数種での再現、ゆらぎの範囲、閉じた周回、近接信号、更新間隔の違い、100ケースのランダム設定テスト：成功。
- 実際のOSRM徒歩ルートとOverpass信号取得：東京駅周辺の約1.24kmの周回で取得成功。信号のルート上への対応づけ計算もテスト成功。
- 接続先からAndroid API 33の端末情報を取得できましたが、インストール・シェル操作は`error: closed`で失敗したため、BlueStacksへのインストール・画面表示・他アプリでの位置更新は未確認です。

Android標準の疑似位置情報APIを使用します。受信するアプリが疑似位置情報を許可するか、どの位置プロバイダを使用するかによって反映されるかが変わります。

## 同梱物

- `RouteGPS.apk`：インストール用APK
- `RouteGPS.apk.sha256`：APKのSHA-256
- `BlueStacks-Setup.cmd` / `.ps1`：Windows向けインストール・許可設定スクリプト
- `platform-tools`：Google公式のADBと必要DLL、ライセンス
- `sample-tokyo-walking.gpx`：実際に取得した徒歩周回ルート
- `sample-tokyo-walking-signals.txt`：同ルートの信号停止距離

スクリプトが設定するのは、このアプリの疑似GPS・位置情報・通知の許可です。スクリプトはroot化や他アプリの設定変更は行いません。
