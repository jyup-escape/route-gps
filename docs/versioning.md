# バージョン管理

専用リポジトリ： https://github.com/jyup-escape/route-gps （非公開）

| 種類 | 名前の例 | 役割 |
| --- | --- | --- |
| 正式版 | `main` | テスト・ビルド・署名検証済みの最新正式ソース |
| バージョン別 | `codex/release-1.1.2` | 実装・検証・配布準備を小さなコミットで保存。反映後も保持 |
| 機能開発 | `codex/paris-rail` | 電車・時刻表など未完成の機能と調査を保存 |
| 正式タグ | `v1.1.1`, `v1.1.2` | 配布ソースを固定。公開済みタグは移動しない |
| 配布物 | GitHub Releases | 署名済みAPK・ビルド元ソースZIPのみ（ハッシュはリリース本文） |

未完成の変更は`main`へ混ぜません。機能単位でコミットし、必要に応じて`v1.2.0-rc.1`などのプレリリースを使います。正式反映はPull Requestで差分を確認し、版番号とCHANGELOGを更新してからマージします。

初回整備では1.1.1の基準版を保存し、1.1.2の実装・配布準備・CIを段階的に保存します。保存されていない古いソースを当時のタグとして捏造しません。

## リリース手順

1. `codex/release-X.Y.Z`を作り、変更ごとにコミットする。
2. Manifestの`versionName`と`versionCode`を増やし、CHANGELOGを更新する。
3. `python setup_tools.py`、`python build.py`でテスト・コンパイル・署名検証を通す。
4. `python package.py`でバージョン名付き配布物を作る。
5. Pull Requestを確認してmainへマージし、同じコミットを`vX.Y.Z`で固定する。
6. ReleaseへAPK・ソースZIPを添付し、変更点と実機検証状況を記載する。

GitHub Actionsはブランチ・Pull RequestでテストとAPKコンパイルを確認します。CIの一時署名鍵は正式配布に使いません。正式APKはローカルの既存署名鍵で作るため上書き更新できます。

ソース・テスト・ビルドスクリプト・説明書・サンプルをGitへ保存します。APK・ZIPはReleasesへ置きます。署名鍵、SDK/JDK、GTFSなど大容量ダウンロード、認証情報はコミットしません。

既存の署名鍵は`tools/routegps.keystore`です。鍵のバックアップは別途保管し、リポジトリや配布ZIPに含めません。

2026-10-02の再配布では1.1.1と1.1.2のタグは固定したまま、当時のソースからクリーンビルドします。1.1.3の機能は過去版へ混ぜません。再配布後のAssetsは各版のAPKとソースZIPの2点に統一します。古いBlueStacks用ZIPとハッシュ添付ファイルはReleaseから外します。ソースZIPは署名鍵やSDK、BlueStacks設定スクリプトを含みません。
